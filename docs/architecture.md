# RecipeFlow 架构与计算规则

知华科技（上海如静知华信息科技有限公司）· https://www.zhuatech.cn/ · 商业咨询微信 zhuatech / zhuatech2

Nginx 同源页面与 `/api` → Spring Security 会话、CSRF → 实时账号、角色和数据范围 → 事务业务服务 → JPA / MySQL 8.4。Flyway V1 身份目录、V2 配方与备料，Hibernate 仅验证结构。初始化只有一个外部配置的管理员和系统目录，业务库为空。

## 成本与计量

单币种人民币；食材报价由采购数量、采购单位、含义明确的总价和净料率组成。kg/g 为重量、l/ml 为体积、pc 为计数，只允许同维度换算，不假设密度。输入用量、采购数量和实际耗用最多三位小数；价格四位小数；净料率两位小数，范围 0.01%–100%。服务端拒绝超精度和指数文本，不静默截断。

配方支持直接食材和批准子配方的份数引用（小数份最多三位），最多40行、展开100种食材、依赖深度5、展开制作步骤200项；子配方制作说明和所需份数随快照保存，并随供餐份数放大提供给执行人。子配方的结构与份数固定到批准版本；成本试算和送审按当前食材目录刷新所有展开食材报价与净料率。任意子版本依赖包含当前配方身份即拒绝，防止跨版本循环。

中间份数比例12位 HALF_UP；汇总净料6位 HALF_UP；毛料＝净料×100/净料率，6位 CEILING；基准单价＝采购总价/基准采购量，12位 HALF_UP；行成本6位 HALF_UP；合计最后到分，单份成本4位。最低有效净料0.000001基准单位。不是无限精度算法；六位量化规则写入快照展示值。零报价允许，表示录入的零食材价格，不表示未知价格。

备料按各配方冻结净料率、单价展开，再按食材归并。同一食材跨配方报价不同时，保留各自成本贡献；执行估值使用计划毛料加权平均单价。实际耗用包含损耗（损耗≤耗用），不重复计价。实际成本是冻结价格的估值，不是实际采购成本、库存过账或完整利润；不包含人工、能源、租金、税费与其他费用。

## 状态与隔离

配方 DRAFT → PENDING → APPROVED；退回→DRAFT；批准后修订→DRAFT，旧批准版本继续保留；草稿或批准可归档。送审快照冻结价格和配方内容，审批时检查食材仍启用且报价版本没有变化，变化后须退回重新送审。历史编辑者不得批准，只有指定审核人可决定。审阅退回不算编辑，修改草稿才记录编辑关系。

备料 DRAFT → RELEASED → RUNNING → COMPLETED；草稿/已发布可取消，运行中不可取消。草稿与发布时均检查当前批准版本；发布后配方改价或修订不改变既有计划。开始、实际耗用与完工只能由指定且仍具备权限的厨房执行人办理。完工必须逐食材录入耗用和逐配方录入产出；零耗用、损耗、产出差异须填写说明。完工结果不可修改。

权限与范围独立：ALL 全部厨房；DEPARTMENT 本厨房；ASSIGNED 本厨房内本人创建/历史编辑/指定审核的配方和本人创建/指定执行的备料计划。食材目录按厨房共享（需 ingredients，改价另需 quote）；已批准配方最小目录按厨房共享给有业务读取权限的人，用于备料与子配方选择。目录管理需具体管理权限及 ALL 范围。审计 ASSIGNED 仅本人动作。

单实例低容量部署的所有业务与管理写事务对主厨房行加锁，获取锁后清除已读身份缓存再核验实时权限。每个业务写入还须匹配版本，防重复提交和并发覆盖；不得据此宣称高并发 SaaS。密码重置、账号/厨房停用立即拒绝旧会话；内存会话重启需重新登录。

## 数据与历史

ingredient、recipe、recipe_line、recipe_editor、recipe_revision、prep_batch、consumption、prep_output、business_event；V1另有身份、菜单、分类、设置和审计表。编号和所属厨房稳定，食材计量维度稳定。历史 JSON 带 SHA256 检查，应用无历史覆盖接口；数据库管理员仍可更改数据和摘要，不是外部不可篡改账本。

无自动收银同步、采购、库存、营养计算、过敏原判定、食品安全认证、AI或第三方集成。
